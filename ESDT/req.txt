- **DevOps engineers** configuring CI/CD and GitOps

- **Security teams** reviewing access patterns and compliance

- **Architects** planning capacity and disaster recovery

- **New team members** understanding the deployment landscape

## 1. Executive Summary

 

The Inshelter pipeline requires the following cloud infrastructure:

 

| Category | Service | Provider | Purpose |

|----------|---------|----------|---------|

| Compute | Azure Kubernetes Service (AKS) | Azure | Container orchestration |

| GPU Compute | AKS GPU Node Pool | Azure | ML inference (NVIDIA) |

| Messaging | Azure Service Bus | Azure | Async inter-service communication |

| Object Storage | Azure Blob Storage | Azure | Point cloud files, IFC outputs |

| Database | MongoDB Atlas | MongoDB Inc. | Workflow state, job tracking |

| Workflow Engine | Temporal | Self-hosted on AKS | Durable workflow orchestration |

| Auth (M2M) | AWS Cognito | AWS | Machine-to-machine tokens (DataRepo) |

| Auth (User) | Microsoft Entra ID | Azure | User/portal authentication |

| Container Registry | Azure Container Registry | Azure | Docker image storage |

| GitOps | Flux CD | CNCF (on AKS) | Continuous deployment |

| Ingress | NGINX Ingress Controller | CNCF (on AKS) | HTTP routing & TLS |

| Autoscaling | KEDA | CNCF (on AKS) | Event-driven pod scaling |

| Secrets | Azure Key Vault + SOPS | Azure | Secret management |

| DNS | Azure DNS | Azure | Domain resolution |

| TLS | cert-manager + Let's Encrypt | CNCF (on AKS) | Certificate automation |

## 2. Cloud Platform Overview

 

### Primary Cloud: Microsoft Azure

 

All compute, storage, and networking runs on Azure. The solution uses Azure-native services with Managed Identity for secure, credential-less authentication between services.

 

### Secondary Cloud: AWS (Limited)

 

AWS Cognito is used solely for machine-to-machine authentication when calling the DataRepo API. This is a cross-cloud dependency inherited from the ESDT platform.

 

### Third-Party: MongoDB Atlas

 

MongoDB Atlas runs as a managed database service, accessed via Private Link from the AKS cluster.

### Scaling Configuration

 

| Service | Min Replicas | Max Replicas | Scaling Trigger |

|---------|-------------|-------------|-----------------|

| Root MS | 1 | 1 | Static (no autoscaling) |

| Segmentation MS | 0 | 5 | KEDA: Service Bus queue depth |

| Post-Processing MS | 1 | 1 | Static (no autoscaling) |

 

### KEDA Configuration (Segmentation)

 

```yaml

pollingInterval: 15 seconds

minReplicaCount: 0

maxReplicaCount: 5

scalingStrategy: accurate

activeDeadlineSeconds: 7200    # Job timeout: 2 hours

ttlSecondsAfterFinished: 3600  # Cleanup after 1 hour

triggers:

  - type: azure-servicebus

    queueName: esdt-s2b-segmentation-queue

    messageCount: "1"           # Scale up on 1 message

    activationMessageCount: "0" # Activate from 0 → 1 immediately

```

## 4. Messaging Infrastructure (Azure Service Bus)

 

### Namespace Configuration

 

| Parameter | Value |

|-----------|-------|

| Service | Azure Service Bus (Premium tier) |

| SKU | Premium (for AMQP over WebSocket, large messages) |

| Namespace | `esdt-{env}-{region}-namespace` |

| Authentication | Azure Managed Identity (azure-identity mode) |

| TLS | Enforced (TLS 1.2+) |

 

### Queues Required (Inshelter)

 

| Queue Name | Purpose | Max Delivery | Lock Duration |

|------------|---------|--------------|---------------|

| `esdt-s2b-root-queue` | Webhook events + completion signals | 10 | 5 min |

| `esdt-s2b-segmentation-queue` | Segmentation task dispatch | 3 | 10 min |

| `esdt-s2b-post-processing-queue` | Post-processing task dispatch | 3 | 10 min |

| `esdt-s2b-temporal-signal-queue` | Legacy signal queue (deprecated) | 5 | 1 min |

 

### Queue Properties

 

| Property | Value | Rationale |

|----------|-------|-----------|

| Max Size | 5 GB | Large point cloud metadata |

| Message TTL | 7 days | Allow for GPU scale-up delay |

| Lock Duration | 5-10 min | Long processing times |

| Dead Letter Queue | Enabled per queue | Poison message capture |

| Duplicate Detection | 10 min window | Prevent reprocessing |

| Sessions | Disabled | Not required |

| Partitioning | Disabled | Premium tier |

 

### Role Assignments (RBAC)

 

Each queue requires two role assignments for the Managed Identity:

 

| Role | Scope | Purpose |

|------|-------|---------|

| Azure Service Bus Data Sender | Per queue | Send messages |

| Azure Service Bus Data Receiver | Per queue | Receive messages |

### Databases & Collections

 

| Database | Collection | Purpose | Estimated Size |

|----------|-----------|---------|----------------|

| `esdt-scan2bim` | `workflow_executions` | Workflow state tracking | ~1 KB per workflow |

| `esdt-scan2bim` | `activity_executions` | Activity logs per step | ~2 KB per activity |

| `esdt-scan2bim` | `app_logs` | Application logs (TTL) | ~500 bytes per log |

| `esdt-scan2bim` | `jobs` | Job deduplication tracking | ~500 bytes per job |

 

### Indexes Required

 

```javascript

// workflow_executions

db.workflow_executions.createIndex({ workflowId: 1 }, { unique: true })

db.workflow_executions.createIndex({ status: 1, createdAt: -1 })

 

// activity_executions

db.activity_executions.createIndex({ activityId: 1 }, { unique: true })

db.activity_executions.createIndex({ workflowId: 1, activityName: 1 })

 

// app_logs (TTL: 30 days)

db.app_logs.createIndex({ createdAt: 1 }, { expireAfterSeconds: 2592000 })

```

### Components Required

 

| Component | Replicas | CPU | Memory | Purpose |

|-----------|----------|-----|--------|---------|

| Frontend | 2 | 500m | 1Gi | gRPC API gateway |

| History | 2 | 1000m | 2Gi | Workflow state management |

| Matching | 2 | 500m | 1Gi | Task queue routing |

| Worker | 1 | 500m | 512Mi | System workflows |

| Web UI | 1 | 200m | 256Mi | Debugging interface |

 

### Temporal Worker (Application-level)

 

The Root MS runs a **separate Temporal Worker process** (`yarn start:worker`) that executes activity implementations. This must run alongside the main NestJS application.

 

### Configuration

 

```env

TEMPORAL_ADDRESS=temporal-frontend.temporal.svc:7233

TEMPORAL_NAMESPACE=default

```

### Path Routing

 

| Path Pattern | Target Service | Port | Rewrite |

|--------------|---------------|------|---------|

| `/orchestrator(/\|$)(.*)` | Root MS | 3000 | `/api/$2` |

| `/segmentation(/\|$)(.*)` | Segmentation MS | 5000 | `/api/$2` |

| `/postprocess(/\|$)(.*)` | Post-Processing MS | 4000 | `/api/$2` |

 

### Ingress Annotations

 

```yaml

nginx.org/client-max-body-size: "1024m"        # Large file uploads

nginx.org/proxy-connect-timeout: "300s"         # Long GPU processing

nginx.org/proxy-send-timeout: "120s"

nginx.org/proxy-read-timeout: "120s"

nginx.org/client-body-buffer-size: "1024m"

```


## 13. Security Requirements

 

### Network Security

 

| Requirement | Implementation |

|-------------|----------------|

| Cluster isolation | AKS with Azure CNI + Network Policies |

| Private endpoints | MongoDB Atlas Private Link, ACR Private Link |

| No public IPs on pods | Internal load balancer + NGINX ingress |

| TLS everywhere | cert-manager with Let's Encrypt (external), mTLS (internal planned) |

| Egress filtering | Azure Firewall / NSG rules |

 

### Application Security

 

| Requirement | Implementation |

|-------------|----------------|

| Auth (external) | Entra ID tokens validated by Root MS |

| Auth (internal) | Cognito M2M tokens for DataRepo, no auth for inter-service HTTP (internal cluster only) |

| Secrets | Never in code; K8s Secrets + SOPS encryption |

| RBAC | Kubernetes RBAC + Azure RBAC (least privilege) |

| Image scanning | ACR vulnerability scanning, Trivy in CI |

| CORS | Restricted to `*.ericsson.net` |

| Dependency scanning | SAST in GitLab CI pipeline |

 

### ABAC (Attribute-Based Access Control)

 

| Service | ABAC Enabled | Provider |

|---------|-------------|----------|

| Root MS | No (inject: false) | Styra/OPA |

| Segmentation MS | No (inject: false) | Styra/OPA |

| Post-Processing MS | Yes (inject: true) | Styra/OPA |

| Metric | Value | Notes |

|--------|-------|-------|

| Scans per day (peak) | 50 | Business hours |

| Avg E57 file size | 1-3 GB | Compressed |

| Avg processing time | 45 min | End-to-end |

### Bottleneck Analysis

 

| Resource | Bottleneck Risk | Mitigation |

|----------|----------------|------------|

| GPU nodes | High — limited availability, expensive | KEDA scale-to-zero, spot instances |

| Post-Processing memory | Medium — 24Gi limit for large scans | Streaming algorithms, file-based processing |

| Service Bus throughput | Low — Premium tier handles thousands/sec | N/A |

| MongoDB connections | Low — connection pooling | Pool size limit per service |

| Blob Storage IOPS | Low — block blob sequential R/W | N/A |

## 16. Disaster Recovery & High Availability

 

### RTO/RPO Targets

 

| Environment | RTO | RPO | Notes |

|-------------|-----|-----|-------|

| Production | 1 hour | 0 (no data loss) | Active-passive or multi-region |

| Acceptance | 4 hours | 1 hour | Single region |

| Test/Dev | 24 hours | 24 hours | Rebuild from GitOps |

 

### HA Design

 

| Component | HA Strategy |

|-----------|-------------|

| AKS | Multi-AZ node pools, pod anti-affinity |

| MongoDB Atlas | 3-node replica set (automatic failover) |

| Service Bus | Zone-redundant (Premium tier) |

| Blob Storage | GRS (production) / LRS (test) |

| Temporal | Multi-replica frontend/history/matching |

| Ingress | Multiple NGINX replicas + Azure LB |

 

### Backup Strategy

 

| Data | Backup Method | Frequency | Retention |

|------|--------------|-----------|-----------|

| MongoDB | Atlas continuous backup | Point-in-time | 7 days (test), 30 days (prod) |

| Blob Storage | Soft delete + versioning | Automatic | 30 days |

| Git (GitOps) | Git history | Every commit | Permanent |

| K8s Secrets | SOPS encrypted in Git | Every change | Permanent |

| Network (egress ~500 GB) | Standard | ~$45 |

| **Estimated Total** | | **~$4,300-$9,100/month** |

 

### Cost Optimization Levers

 

| Strategy | Savings | Trade-off |

|----------|---------|-----------|

| GPU spot instances | 60-80% on GPU | Possible preemption |

| KEDA scale-to-zero | Eliminates GPU idle cost | 2-5 min cold start |

| Reserved instances (1yr) | 30-40% on standard nodes | Commitment required |

| Blob lifecycle (cool tier) | 50% on old data | Slower access to archived files |

| Dev/Test pricing | 50-70% on non-prod | Limited SLA |
